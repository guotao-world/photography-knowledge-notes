# 相机 Log 格式视频

参考链接：https://www.imagejoy.com/article/651

## 一、主要流程

摄影/视频 N-Log + H.265 编码流程。

### 1. 相机采样

光学信号 → 传感器 → ADC → 数字亮度值。这是线性光度值（Linear Light）。

### 2. LOG 映射（N-Log）

将线性亮度值套上 Logarithmic Curve。

目的：压缩高光、拉伸暗部 → 最大化动态范围。

输出的像素值范围通常是 10bit 或 12bit（线性映射到 LOG 空间）。

### 3. 色彩处理/白平衡（可选）

对 LOG 数据进行白平衡、色彩空间转换（如 DCI-P3/Rec.709），但不改变 LOG 曲线亮度分布。

### 4. 压缩编码（H.264/H.265）

LOG 视频数据作为输入帧，H.265 对帧进行压缩存储，输出 MP4/MOV 容器。H.265 压缩过程中尽量保留 LOG 的亮暗关系。

### 5. 存储/播放

- 播放器默认解码 H.265 → 显示灰蒙蒙 LOG 画面
- 后期软件（达芬奇）应用 LUT → 转回可视化 Rec.709/Rec.2020

## 二、基本公式

Y = K·log(1+L)

L = 输入亮度，可以是任意连续值，不一定整数 EV。

LOG 曲线是连续函数 → 即使暗部亮度很低（EV < 1），也能映射到像素值。所以从数字编码角度，不会被"档位限制"，只是人或摄影书写曝光通常用 EV 档表示。

## 三、光档位概念

### 1. 整档（1EV）

- 每增加一档，光量翻倍
- 每减少一档，光量减半

### 2. 半档，三分之一档

现代相机通常支持可调分度：1/2EV 或 1/3EV，这样可以更精细地控制曝光。

### 3. 零档（0EV）

只是一个相对参考值，并不是表示"无光"。

EV=0 时，相机有固定光量参考（通常是 ISO100、快门 1s、光圈 f/1.0 下的标准曝光）。

## 五、具体讲解

大家的相机可以 10 位元（bits）或以上来记录颜色，但为了简化计算，假设相机的位元深度（Bit Depth）只是 8-bit，即只可以 8 位元来表达色彩。8 位元可以产生 256（2 的 8 次方）个数值。换句话说，8 位元可以表达 256 个光度。以 0 表示最黑，而 255 表示最白。

感光元件的「模拟数码转换器（A/D Converter, ADC）」会把接收到的曝光量转成 0-255 的数值。让我们把曝光等级与相对明亮值绘在图表上。

### 1. 线性编码亮度分布图

X 轴：曝光等级（0-8 级），Y 轴：明亮值（0-255）。曲线呈指数增长：曝光等级 0-4 级仅占用 0-16 的明亮值范围（约 1/16 的位深），而 7-8 级占用 128-255 的范围（约一半的位深）。说明线性编码下高光占用大量位深，暗部位深不足。

X 轴表示曝光等级，每增加一个等级，曝光量会增加一倍。假设相机的动态范围是 8 级，就在 X 轴列出 8 个曝光等级。Y 轴则表示每个曝光等级的光度（0-255）。

可有发现由 2^7 到 2^8 占用了 Y 轴的一半长度？全条 Y 轴的最大值是 255，而 2^8 减 2^7 已是 128。单是这段高光位已占了一半的位元深度（Bit Depth）。

最可笑是相机只用了 1/16 的位元深度（Bit Depth）来表达由 0 到 2^4，一共 4 级的明亮度。以 1/16 的 Y 轴来记录首 4 个曝光等级的明亮度，实在太"偏心"了吧！这也解释了数码相机对暗位处理为何如此差劣。

### 2. LOG 就是解决办法

之前说过「模拟数码转换器（A/D Converter, ADC）」把光度转成电压的过程是线性（Linear）的。只要在编码及压缩前，把曝光值套上 LOG 曲线函数，便可拉近各曝光等级所占用的位元深度（Bit Depth）。

### 3. LOG 编码亮度分布图

X 轴：曝光等级（1-8 级），Y 轴：明亮 LOG 值。曲线近似线性增长：各曝光等级获得相对均匀的 Y 轴长度分配，位深在明暗区间分布更均衡。LOG 曲线通过对数变换压缩高光、扩展暗部，解决了线性编码高光位深浪费的问题。

从上图可以看到各曝光等级都获得差不多的 Y 轴长度，即是大家的位元深度（Bit Depth）都差不多。解决了之前，相机花了超过一半的位元深度（Bit Depth）来记录最光一级的问题。
